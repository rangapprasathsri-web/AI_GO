# Assumptions & Methodological Guardrails

This document records all explicit assumptions, simulated data caveats, and architectural design choices made in the Adaptive AI Request Optimizer.

## 1. Simulated Numbers & Pricing
- **Assumption**: All cost figures ($0.0005 reuse, $0.002 template_outline, $0.01 draft, $0.04 standard, $0.12 premium) are **simulated placeholders** (`source: placeholder`, `is_simulated: true`).
- **Guardrail**: No prices are invented or claimed to represent actual third-party vendor charges. Cost savings are strictly computed from running the exact same workload under both baseline and optimized policies.
- **Requester Display**: Currency is hidden from requesters by default (`show_relative_cost: true`, `hide_currency_from_requester: true`), who instead see relative effort levels (e.g., "about 1/15 the cost of Print-quality"). District admins see simulated dollar amounts.

## 2. Workload & Category Mix Distribution
- **Assumption**: The default evaluation workload distribution uses:
  - 70% Colouring worksheets (line-art outline, B&W)
  - 15% Flashcards (4x6, simple colour)
  - 10% Detailed illustrations (A4, standard colour)
  - 5% Printed posters/banners (A1, high-DPI colour)
  - 30% Repeat rate for previously generated subjects
- **Basis**: The district audit established that "most requests were simple black-and-white outlines for children to colour, yet ran at maximum poster settings".
- **Impact**: Attributed savings depend on this realistic district workload mix. A different real-world distribution would yield different aggregate numbers.

## 3. Savings Attribution Decomposition
- **Assumption**: Total cost savings decompose into three distinct levers:
  1. `reuse_savings`: Reusing approved existing assets from the library at $0.0005 instead of re-generating.
  2. `template_savings`: Using deterministic non-generative vector line art at $0.002 instead of invoking generative AI.
  3. `lower_tier_savings`: Right-sizing generative parameters (draft/standard vs premium) to match the purpose quality floor.
- **Invariant**: The engine mathematically guarantees `reuse_savings + template_savings + lower_tier_savings == total_savings`.

## 4. Quality Floor & Proxy Checks
- **Assumption**: Automated quality checks (output exists, valid format, resolution at DPI, colour mode, ink coverage [0.03, 0.25]) are **automated proxy checks**.
- **Guardrail**: Every response, UI component, and evaluation report clearly displays the disclaimer:
  *"These are automated proxy checks, not a judgement of whether the output is actually pedagogically suitable for its intended purpose."*
- **Human In The Loop**: An optional 1-to-5 human rating widget allows requesters to evaluate pedagogical fitness after automated checks pass.

## 5. Child Safety & Privacy
- **Assumption**: Personal data filtering rejects prompts containing student emails, phone numbers, student ID numbers, or names in context (e.g. `student: John Doe`).
- **Guardrail**: Personal data is rejected at intake, scrubbed from logs and database records, and strictly excluded from the reuse library.

## 6. School Quotas & Approval Ceilings
- **Assumption**: The district admin configures a monthly spend ceiling per school (default: $20.00/month).
- **Enforcement**:
  - Reaching 80% triggers a warning in the response (`Budget alert: 80% used`).
  - Reaching 100% routes subsequent requests to `AWAITING_APPROVAL` status (not silently rejected or executed).
  - Individual requests exceeding the single-request approval threshold ($0.10) also require approval or justification.

## 7. Engine Isolation
- **Rule**: The core engine (`backend/engine/`) has **zero imports** from domains, adapters, or API code.
- **Enforcement**: Tested continuously via AST and import inspection in `test_engine_has_no_imports_from_domains_adapters_or_api`.

## 8. Data Origin Categorization
- **Rule**: Every cost, latency, and quality value carries a `data_origin`:
  - `simulated`: Synthetic values generated by test mocks.
  - `estimated`: Pre-execution calculations based on published rate sheets.
  - `provider_reported`: Upstream API usage metrics reported in HTTP response payloads.
  - `billing_confirmed`: Verified post-invoice financial reconciliation.
- **Guardrail**: Origins are never blended into an aggregated total without presenting the explicit split.

## 9. Optimizer Overhead Accountability
- **Assumption**: Performing semantic intent analysis incurs its own compute overhead ($0.001 cost, 0.15s latency).
- **Guardrail**: LLM intent analysis costs are explicitly added into actual request costs and breakdown items (`llm_analysis_overhead`), ensuring the optimizer cannot claim inflated net savings.
- **Rules-First Bypass**: Unambiguous requests classified with high confidence by deterministic keyword rules bypass external LLM analysis completely to preserve budget.

## 10. Provider Pricing & Offline Contract Testing
- **Assumption**: Documented rates for DALL-E 3 and DALL-E 2 reflect official OpenAI pricing published as of October 2026 (`source_updated_at: 2026-10-01`).
- **Safety Margin**: A configurable safety margin (default 0%, up to 15%) is applied when upstream pricing fluctuates or is uncertain.
- **Contract Testing**: All provider adapters support HTTPX mock transports, guaranteeing that the automated test suite never incurs paid API charges or requires live external credentials.

## 11. Official Problem Statement: Resource Units & Counterfactual Savings
- **Core Unit Proxy**: Units are calculated via the documented first-order formula:
  $$\text{Units} = \text{Steps} \times \left(\frac{\text{Width} \times \text{Height}}{10^6}\right) \times \text{Model Factor}$$
  This is a defensible relative proxy for computational effort; real energy consumption depends on specific GPU hardware, batching, and kernel optimizations.
- **Counterfactual Avoidance**: "Saved" means estimated avoided compute versus running the same prompt at Maximum tier, which did not happen. It is always labeled as `"estimated savings vs maximum tier (not run)"`.
- **Honest Non-Clamping**: If a user overrides above Maximum or bad config sets selected above Maximum, savings are negative, not clamped to zero.
- **Failures Add Spent Units, Zero Savings**: If a generation fails, spent units are added to consumption, but zero savings are credited.
- **Energy & Carbon Prohibition**: Energy in Wh and CO2 return `null` (never zero or fabricated values) when `energy_model.enabled` is false.
- **Hard Resource Unit Budgets**: Budgets are enforced in compute units (`per_request_units_max: 120`, `session_units_max: 2000`). Requests exceeding the hard budget are blocked or require user adjustment.

## 13. Competitiveness Upgrades: Measurement Levels, Fit Proxies & Benchmarks
- **Measurement Level**: Detected as **Level 0 (Simulated / Mock Provider)**.
  - Hardware: Intel(R) Core(TM) i5-13420H, no NVIDIA GPU, Intel RAPL counters permission-restricted to root.
  - Upstream Provider: No `OPENAI_API_KEY` configured in `.env`.
  - Invariant: Energy in Wh and CO2 return `null`. Compute units are explicit relative proxies (`steps * megapixels * model_factor`). Simulated values are never claimed as measured.
- **Automated Purpose-Fit Proxies**:
  - Automated mathematical proxy checks using Pillow and numpy (near-white background fraction, saturation, dark line coverage, Laplacian variance for sharpness, pixel dimensions).
  - Disclaimer: *"These are automated proxy checks, not a judgement of whether a person will like the image."*
  - Fit Verdicts: `Yes` (all pass), `Partly` (minor criteria fail), `No` (critical floor fails).
- **Savings Ineligible on Unfit Results**:
  - If `fit_verdict == 'no'`, claimed savings are 0.0 units (savings ineligible). The compute units spent are counted in full as waste.
- **Good Enough? Feedback Flow**:
  - User feedback (`yes` or `no`) is persisted to `user_feedback` table.
  - Rating `no` provides a suggestion to try the next tier up, but never auto-escalates silently.
- **Benchmark Sample Disclaimer**:
  - `benchmarks/prompts.json` contains 20 fixed prompts across 5 purposes.
  - Disclaimer: *"We wrote these prompts for comparative evaluation; they are not a representative sample of real-world usage."*
- **Live vs Benchmark Maximum Baseline**:
  - In normal live usage, Maximum baseline is a counterfactual calculation labeled `"not run"`.
  - In the multi-prompt benchmark, the Maximum baseline is **actually executed** for every prompt to yield measured baseline data.

## 14. Firebase Realtime Database Integration & Architecture
- **Primary Store**: Firebase Realtime Database (RTDB) project `ai-go-a6a7a`, instance `ai-go-a6a7a-default-rtdb`, database URL `https://ai-go-a6a7a-default-rtdb.firebaseio.com`.
- **Dual-Storage Contract**: Both `FirebaseRepository` and `SQLiteStorage` implement the exact same `StorageInterface` in `backend/storage/base.py`.
- **Backend Authoritative Writer**: All writes go through the backend using Firebase Admin SDK (Python). Client browsers never write computed resources, savings, or fit verdicts directly.
- **Frontend Live Sync**: Frontend uses Firebase Web SDK modular API to listen to user generation records and running totals via `onValue`/`onChildAdded`.
- **Graceful Fallback & Outbox**: If Firebase is unreachable, misconfigured, or credentials are absent, the application logs a warning, falls back to `SQLiteStorage` without crashing, reports `storage_backend: "sqlite (fallback)"` in `/health`, and queues records in an outbox for subsequent replay.
- **Engine Zero-Import Invariant**: The core engine (`backend/engine/`) has **zero imports** of Firebase code (`firebase_admin` or `google.cloud`). All persistence logic is isolated in `backend/storage/`.
- **Security Invariant**: Service account credentials and private keys are never committed to git, logged, or sent to client browsers.

## 15. Feature 1: ColourReady Local Line-Art Pipeline
- **Purpose Gating**: Strictly restricted to line-art purposes (`coloring_sheet`, `colouring_worksheet`). Non-line-art purposes skip execution deterministically with draft output untouched (`skipped: true`).
- **Processing Chain**: Deterministic 6-step local post-processing:
  1. Grayscale conversion.
  2. Denoising via median filter.
  3. Adaptive Gaussian thresholding.
  4. Smooth Lanczos upscale to target print dimensions (default A4 @ 300 DPI: 2481×3507 portrait or 3507×2481 landscape).
  5. Anti-aliasing Gaussian blur.
  6. Re-thresholding to strictly binary {0, 255} pixel values.
- **Honesty Labels & Latency**: Wall-clock pipeline execution time is explicitly labelled `Measured`.
- **Added Units Proxy**: Local processing time is converted into relative compute units via configurable factor (`time_to_units_rate: 0.1`) and added to unit totals.
- **Real-Cost Caveat**: Every ColourReady outcome prominently displays and stores the caveat: `"cost does not scale exactly with pixels"`.
- **Engine Isolation**: `backend/engine/colour_ready.py` imports only standard libraries, OpenCV, NumPy, and Pillow; zero imports from `backend.domains`, `backend.adapters`, or `backend.api`.
